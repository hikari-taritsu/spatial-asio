# 验证记录 · 0.1.1-preview.1

验证日期：2026-10-14。以下区分算法回归、真实链路测试与尚未覆盖的范围。

## 算法与自动测试

- 七种布局直接渲染，共 33,957 个坐标：非负有限增益、单位功率、LFE 隔离、左右镜像（允许原有坐标量化误差），以及三个轴的连续移动扫描。
- 验证实际 MetadataRenderer 输出与目标布局声像增益一致；不是只测试独立几何函数。逐布局覆盖 16 种床声道语义、缺失声道的位置重分配、增益渐变、首块、对象中止/重启、不同块切分、Reset 和 Flush。
- 时间轴以固定环形存储替代逐帧 map 分配；双流同位置混合与多次环绕输出完全一致。
- 9.1.6 对旧本地已验证共享实现：800 × 127 帧、4 个移动对象，1,625,600 个输出样本，最大误差 0。
- 另对修改前后的完整原生时间轴基准输出做 SHA-256：4/32/160 对象各 1,200 × 128 帧，含对象身份变化、数量变化和增益更新，PCM 字节完全相同。摘要：`e363052defa08a55e8fd96edb80cdd6fec36e0c8ab67defc7b8fe68e42c4adb1`。
- 模拟 ASIO：16 通道映射、初始化静音、精确欠载计数、暂停/恢复、缓冲重建、释放与失败重开。
- 故意堵塞遥测输出管道：生产线程继续运行，结束时可取消阻塞的写入；不丢弃音频数据。
- 桌面：七个配置预设、序列化、重复输出拒绝，以及内置字体实际加载检查。
- WPF 实际离屏绘制：默认尺寸和最小窗口内容尺寸检查，圆形比例保持、标签不重叠。没有使用 Computer Use。

## 性能与延迟

相同机器、Release、相同输入，代表性复测（毫秒/包；包含原生场景与时间轴操作，不包含界面、Python 和驱动）：

| 对象数 | 修改前平均 | 修改后平均 | 减少 |
|---:|---:|---:|---:|
| 4 | 0.1060 | 0.0425 | 60% |
| 32 | 0.1675 | 0.1003 | 40% |
| 160 | 0.4183 | 0.3531 | 16% |

这不是总体游戏 CPU 使用率。计时有系统波动；两个版本的原始 PCM 摘要相同。

以 128 帧/48 kHz 为例：原来的捕获缓冲 60 ms + 最低启动积累 20 ms = 80 ms；本机 12 ms 配置 + 两个驱动周期 5.33 ms = 17.33 ms，程序缓冲预算减少约 **62.67 ms**。此外仍有 10.67 ms 算法前视、驱动报告的 22.67 ms，以及未在这里完整测量的游戏、Windows 音频图、传输和扬声器延迟。实际队列会随回调相位变化；不能把这个差值称为声学端到端实测改善。

新配置默认 32 ms，升级保留已有配置；本机在上述验证后单独设为 12 ms。允许 8–500 ms，遇到游戏负载或系统调度抖动导致计数增长时提高缓冲。未削减声像平滑/前视，也未丢弃音频样本来追赶时间。

## 复现与范围

`tools/Build.ps1` 运行 CTest 与桌面自检；`tools/NativeSpatial/python/python.exe tests/test_capture.py` 验证协议。`SpatialASIO.Benchmark.exe [PCM输出路径]` 生成确定性基准。可选 `SpatialASIO.OracleCheck.exe <自己的旧本地共享渲染DLL>` 进行迁移对照，DLL 不发布。

`SpatialASIO.NativeFixture.exe <已启用空间音效的端点ID> 128 60` 提交静音的移动/启停对象；必须配合以管理员权限运行的正式引擎与自己的 ASIO 配置，检查 status 遥测中的计数。该工具仅为显式启动的开发测试，不由 CTest 自动运行，不随安装版提供。

尚未覆盖每个 Windows/ASIO 驱动组合，未把本机测试推广为所有机器的稳定性保证。其他目标布局尚未逐一与官方 Dolby 渲染器对照；9.1.6 的旧结果回归也不代表对全部 Dolby 参数的完整复刻。
